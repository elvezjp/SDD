# プロジェクト管理ツール の30日導入プラン

2026-11-19 に、第1週は自分で組み、第2〜4週は AI の素案を自分で直した。

## 第1週（1〜7日目）体験

| 曜日 | タスク | 7つの工程との対応 | 時間目安 |
|------|--------|------------------|----------|
| **月曜日** | 担当1人がリポジトリを作り、README.md に「プロジェクト管理ツール」の目的・背景を書く | ①原則決定（簡略版） | 10分 |
| **火曜日** | 想定ユーザー1種類と主要機能5つ以内を README.md に箇条書きで追加する | ②企画・要件（簡略版） | 15分 |
| **水曜日** | README.md をブラウザの AI チャットに貼り、足りない点を質問してもらう | ③設計計画（簡略版） | 20分 |
| **木曜日** | 主要機能を小さなタスクに分け、README.md に書き出す | ④タスク分割（簡略版） | 15分 |
| **金曜日** | README.md をレビューし、抜けた日の分を確認して、振り返りを README.md に書く | ⑥検証・受入（簡略版） | 30分 |

## 第2週（8〜14日目）習慣化

毎朝の README 更新が習慣になり、主要機能1つの仕様と指標の記録が可能な状態を構築する

- [ ] 毎朝 README に1行足し、朝会で検討事項を報告する
- [ ] 夕会までに主要機能のうち1つの仕様を README に書く
- [ ] 数える指標を決め、毎日の記録表を作り確認する
- [ ] 主要機能1つの仕様を8割程度確定させる
- [ ] 別の主要機能についても1つの仕様を書き始める

## 第3週（15〜21日目）プロセス改善

PR と確認項目で、仕様の抜けや食い違いを仕組みで見つけられる

- [ ] PR を導入し、承認者を1〜2名決める
- [ ] PR テンプレートに確認項目を3つ置く
- [ ] 前週に決めた主要機能1つの仕様を参考に、別の主要機能1つの仕様を PR で書き進める
- [ ] 仕様の抜けや食い違いを補正し、合意した仕様を README に書く
- [ ] 別の主要機能で出てきた仕様で別の機能に横展開すべき仕様がないか確認する

## 第4週（22〜30日目）定着と評価

30日の成果を数字で説明でき、次の一歩を自分たちで決定する

- [ ] 取り決めた指標を集計し、30日の変化をまとめる
- [ ] 関係者向けに成果を1枚にまとめて見せる
- [ ] 振り返り会を開き、次の一歩を決める
- [ ] 仕様が未確定の別の主要機能について仕様を書き進める

型：書籍『仕様駆動開発 実践入門』第5章の最初の1週間と、SDD リポジトリの 90日間導入プランの前半。
